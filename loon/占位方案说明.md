# 两个方案的差别

现在有 **两个** Loon 插件，二选一（不要同时开）：

| 插件 | 做法 | 效果 | 风险 |
|---|---|---|---|
| [番茄小说去广告.plugin](番茄小说去广告.plugin) | 直接 REJECT，请求发不出去 | 广告位彻底消失，页面不占位 | 可能触发 SDK 兜底，出现空白页 |
| [番茄占位.plugin](番茄占位.plugin) | **不拦截**，改写返回的文案 | 广告位仍在，但显示「广告位已屏蔽」 | 无——布局和接口调用完全不变 |

你想先看效果的，用**第二个**。

---

## 番茄占位.plugin 怎么工作

```
App 请求广告  →  Loon 照常转发  →  服务端返回真实广告 JSON
                                        ↓
                              adPlaceholder.js 改写文案
                                        ↓
              App 收到的是：标题=「广告位已屏蔽」、按钮=「查看」、描述=「（Loon 替换）」
                   但图片、视频、跳转链接、卡片结构全部保留
```

因为只改字符串字段，Lynx 的渲染节点数量、布局参数都不变，**不会出现空白或崩溃**。

## 改写了哪些字段

从二进制里核对出来的真实字段名（`analysis/reading_strings.txt:849960` 一带的 `SSReadingAdContentModel`）：

**标题类 → 「广告位已屏蔽」**
```
ad_title / adTitle / title / brand_name / brandName
app_name / appName / app_title / appTitle
```

**按钮类 → 「查看」**
```
button_text / buttonText / ad_buttonText / cta_text / ctaText
download_text / action_text
```

**描述/标签类 → 「（Loon 替换）」**
```
sub_title / subtitle / desc / description / ad_description / slogan
sellingTag / marketTag / recommend_reason / recommend_text / ad_source
```

## 安装

1. Loon → 配置 → 插件 → `+` → 本地文件 → 选 `番茄占位.plugin`
2. 把 `adPlaceholder.js` 放到脚本目录（Loon 的 Scripts 文件夹），
   或者把 `script-path` 改成你实际的路径
3. 确认根证书已装且已在「证书信任设置」里打开
4. 打开番茄，翻几页看效果

## 需要留意的

**如果文案没变**，说明：
- 广告卡片是预渲染缓存（`preload_lynx_bundle`），请求不会重新发 → 需要杀掉 App 重开
- 或者广告字段不在我列的范围里 → 把 Loon 的「请求记录」里那条响应发我，我按实际字段补

**如果页面变空白**，说明改到的字段不只是文案（比如 `title` 同时被用作布局 key）。
把 `adPlaceholder.js` 里 `SUB_KEYS` 中的 `"desc"`、`"description"` 删掉再试。

## 我为什么先给你占位方案

自签那轮最大的教训是：**一次改太多，出问题分不清是哪一步。**
占位方案不动请求、不动结构，只换字，是能最快看到「Loon 能不能进屋」的验证方式。

如果占位显示正常，说明 MitM 通了、脚本生效了，那再切到 REJECT 版就是顺理成章的事。
