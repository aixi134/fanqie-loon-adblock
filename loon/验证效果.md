# 怎么确认占位方案生效了

## 现在的占位长什么样

脚本里只有三个替换目标：

| 位置 | 替换成 | 变量 |
|---|---|---|
| 广告标题 | **广告位已屏蔽** | `MAIN` |
| 广告描述/标签 | **（Loon 替换）** | `SUB` |
| 广告按钮 | **查看** | 硬编码 |

所以广告卡片会变成这样：

```
┌─────────────────────────────┐
│  [广告图片/视频 保持不变]     │
│                             │
│  广告位已屏蔽                 │  ← 原 ad_title / title
│  （Loon 替换）                │  ← 原 desc / sellingTag
│                             │
│  [ 查看 ]                    │  ← 原 button_text
└─────────────────────────────┘
```

**图片和跳转链接都没动**，只有文字变了。这是刻意的：删物料会让 Lynx 渲染崩溃。

---

## 三个确认方法，从最快到最可靠

### 方法 1：看广告卡片的文字（最快）

进一本书，翻到广告出现的那一页。

| 你看到的 | 结论 |
|---|---|
| 标题写着「广告位已屏蔽」 | ✅ 脚本生效了 |
| 标题还是原来的广告文案 | ❌ 脚本没跑，看方法 2 |
| 完全没有广告卡片 | ℹ️ 广告被拦掉了（REJECT 版的行为）或这页本来就没广告 |

> 注意：番茄有**预加载缓存**（`preload_lynx_bundle`），
> 已经缓存进本地的广告不会重新请求。
> 如果翻了 20 页都没看到文字变化，**先杀掉 App 进程重开**再测。

### 方法 2：看 Loon 日志（确认脚本有没有执行）

```
Loon → 底部「日志」
→ 找 URL 含 ad.zijieapi.com/api/ad/v1/banner 的那条
→ 点进去
```

| 日志里看到的 | 结论 |
|---|---|
| 有「脚本」标记 / 显示 script 处理 | ✅ 脚本被调用了 |
| 有这条请求但没有脚本标记 | ❌ `[Script]` 规则没匹配上（检查正则） |
| 完全找不到这条请求 | ❌ MITM 没生效（证书没信任 / 主机名没加），或广告走了缓存 |

### 方法 3：制造一个一定能触发的场景

用 [番茄分步验证.plugin](../loon/番茄分步验证.plugin) 里的思路：

1. 临时把 `MAIN` 改成一句很显眼的文字，比如 `【测试占位999】`
   （改 GitHub 上的 `loon/adPlaceholder.js`，或者 Loon 里直接改本地脚本）
2. 杀进程重开，翻页
3. 只要屏幕上任何位置出现 `【测试占位999】`，就说明链路全通

改回原文案：把 `MAIN` 改回 `广告位已屏蔽`。

## 如果广告文字没变

按这个顺序排查：

1. **杀进程重开** —— 90% 的情况是缓存
2. **确认 MITM 主机名**：Loon → 配置 → 全局 → 主机名，含 `ad.zijieapi.com`、`reading.snssdk.com`、`ib.snssdk.com`
3. **确认证书信任**：设置 → 通用 → 关于本机 → 证书信任设置 → Loon CA 开启
4. **确认脚本加载**：Loon → 配置 → 脚本，看 `adPlaceholder.js` 是否在列表里且无报错
5. **检查字段名**：可能这个广告位的字段不在我列的名单里

第 5 种情况的处理：在 Loon 日志里把那条响应**导出 JSON**，看实际字段名，
然后告诉我，我把它加进 `TITLE_KEYS` / `SUB_KEYS`。

---

## 想换个占位文案

直接改 `loon/adPlaceholder.js` 顶部两行：

```js
const MAIN = "广告位已屏蔽";    // 改成任意文字
const SUB  = "（Loon 替换）";    // 改成任意文字
```

改完提交到 GitHub，Loon 下次加载会拉到新版（有缓存的话在「脚本」页手动刷新）。

或者更快：Loon → 配置 → 脚本 → 找到 `adPlaceholder.js` → 直接编辑 → 保存 → 杀进程重开。
