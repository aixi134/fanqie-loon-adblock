# Loon 全量去广告 —— 安装与验证

插件：[番茄小说去广告.plugin](番茄小说去广告.plugin)（17 条规则）

## 前提

1. 手机上的自签版（`com.dragon.read-noad`）**先删掉**，从 App Store 装回官方版。
   自签版拿不到正文解密 key，留着没法看书。
2. Loon 已装好并能正常代理。

## 安装

### 1. 装 Loon 根证书

Loon → 配置 → 证书管理 → 生成/安装证书 → 按提示装描述文件
→ **设置 → 通用 → 关于本机 → 证书信任设置 → 打开 Loon 的开关**（这一步不做，MITM 全部失效）

### 2. 导入插件

Loon → 配置 → 插件 → `+` → 本地文件，选 `番茄小说去广告.plugin`。

或者直接把 `[Rule]` 和 `[MITM]` 两段内容粘贴进你的主配置。

### 3. 确认 MITM 主机名

插件里的 `[MITM] hostname` 只加了两个域：

```
ad.zijieapi.com, reading.snssdk.com
```

如果你的 Loon 配置里已有 `[MITM] hostname`，`%APPEND%` 会自动追加，不用手动改。

## 装好之后怎么看效果

打开 App → 书架 → 进一本书 → 连续翻 10 页以上 + 翻过章末。

**判断标准：**

| 现象 | 结论 |
|---|---|
| 插页广告没了，正文正常 | ✅ 成功 |
| 正文也加载不出来 | ❌ 说明 MITM 有问题，先把 `[MITM] hostname` 里的 `reading.snssdk.com` 删掉再试 |
| 出现空白页/占位卡片 | ⚠️ REJECT 让 SDK 走了兜底分支，见下面 |
| 有广告但变少了 | ℹ️ 部分物料来自正文响应或本地缓存，属于拦不到的部分 |

## 如果出现空白占位卡

把 `[Rule]` 里对 `ad.zijieapi.com/api/ad/v1/banner` 的 REJECT 换成返回空 JSON 的脚本。
在插件里加一段：

```
[Script]
http-request ^https?://ad\.zijieapi\.com/api/ad/v1/banner/ script-path=rejectBanner.js, requires-body=false
```

`rejectBanner.js`：

```js
const body = JSON.stringify({ code: 0, message: "success", data: { ad_data: [], ad_items: [], list: [] } });
$done({ status: 200, body, headers: { "Content-Type": "application/json" } });
```

这样 SDK 会走 `list empty` 正常分支（二进制里的日志串 `request banner list empty:`），
而不是走网络错误分支。

## 已知拦不到的部分

| 广告位 | 原因 |
|---|---|
| 段中内嵌广告（inline_trigger_ad） | 物料随正文一起下发，没有独立请求 |
| 离线假广告页 | 纯本地行为，`defaultAd` / `offline_fake_ad_reverse_v739` |
| 部分底栏 banner | SSR 预取进正文 ADM 缓存，可能不产生新请求 |
| QUIC 流量 | TTNet 有 `supports_quic`，UDP/443 不走 MitM |

唯一需要担心的是 **证书固定（pinning）**。二进制里只找到 Chromium 的 `StaticKeyPinningEnforcement` 通用开关，
没有针对自家域名的 pin 列表，所以大概率能连。
如果打开 App 后书架都刷不出来 → 那就是有 pinning，把插件关掉即可恢复，不会损坏任何东西。
